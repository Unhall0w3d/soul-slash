# Capability and Skill Foundation A2

## Purpose

Extend Soul's machine-readable self-recognition into one read-only Skill Studio
conversation surface, reconcile A1 status records, and define the first
curated fundamental-skill cohort without importing unreviewed online behavior.

## Skill Studio inspection

An explicit Chat or Voice Presence request may inspect:

- proposal count, exact IDs, titles, stages, and Gate 1 state;
- Beta count, IDs, maturity, run eligibility, current test state, and promotion
  state; and
- current production registry entries and declared availability or risk.

An exact current proposal ID or exact title may return proposal detail. An
exact Beta ID may return Beta detail. Inspection returns current local
projections and must not substitute model memory or conversation history.

## Authority boundary

Conversational inspection cannot prepare or execute proposal approval, Beta
workspace creation, Dev drafting, Beta execution, Gate 2 approval, production
promotion, proposal closeout, rejection, or deletion. These remain exact
Operator-controlled Skill Studio actions.

Every inspection terminates as `complete`, `failed`, `awaiting_input`,
`canceled`, or `blocked_for_human_review`. It adds no poller, watcher, service,
scheduled task, automatic retry, or private memory.

## Fundamental Skill Cohort A1

The next cohort is a reviewed implementation queue, not an availability claim.
Candidates are ordered by reusable value and ability to preserve bounded local
authority:

1. `files.inspect` — list, stat, and read bounded content beneath one explicit
   approved root; no writes, symlink escape, hidden broad scan, or secret
   collection.
2. `network.diagnose` — run bounded read-only DNS, route, address, socket, and
   explicit-target reachability checks; no broad network scan or configuration
   mutation.
3. `repository.inspect` — inspect status, branch, log, and diff in one explicit
   repository; no checkout, staging, commit, push, or remote mutation.
4. `workspace.artifact.compose` — package the existing preview/digest-gated
   artifact workflow as a modern skill without creating a second writer.
5. `web.research` — package the existing bounded SearXNG workflow as a modern
   skill while retaining untrusted-source and memory-promotion boundaries.

Each candidate requires its own brief, deterministic tests, review artifact,
registry and invocation entry, and lifecycle behavior before implementation or
availability. Existing execution paths must be wrapped rather than duplicated.

## Explicit deferrals

The cohort does not import arbitrary Codex, marketplace, or online skills. It
does not add arbitrary shell execution, package installation, browser/account
automation, messaging, calendars, background scheduling, credentials, or
privileged mutation. Such capabilities require separate source, license,
dependency, privacy, authority, and threat review.

## Acceptance

- explicit Skill Studio inspection routes deterministically in Chat and Voice;
- ordinary discussion of skills remains conversation;
- live proposal, Beta, and production state is reported without mutation;
- every mutating Studio request stops at its owning human gate;
- capability, invocation, skill, guide, and tracker records agree; and
- the fundamental cohort is documented as planned rather than registered or
  advertised as available.
