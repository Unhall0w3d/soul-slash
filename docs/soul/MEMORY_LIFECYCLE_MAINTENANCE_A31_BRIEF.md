# Memory Lifecycle Maintenance A31 Brief

## Status

Human-authorized candidate slice. The Operator approved continuing beyond the
first audited A30 consolidation while preserving the existing Core-aware worker
and timer.

## Objective

Let the existing bounded memory lifecycle activation process one eligible exact
duplicate after ordinary observation derivation and admission work is clear.
No additional timer, service, daemon, model call, or network dependency is
introduced.

## Policy

- Ordinary A16 derivation and admission work always has priority.
- One activation performs either one ordinary lifecycle cycle or one A30 exact
  duplicate consolidation, never both.
- A30 remains the only consolidation policy and mutation implementation.
- Free and Creative Core skip behavior, stable work-derived request identity,
  timer cadence, timeout, and hardening remain inherited from A17.
- A canonical consolidation explicitly reports that projection reconciliation
  is required. The worker does not rebuild the local index or remote projection.
- Audit-chain verification, rollback references, protected-memory exclusion,
  and content-free status receipts remain mandatory.

## Acceptance

Deterministic verification proves lifecycle priority, one-mutation bounds,
stable work identity, no-work abstention, rollback visibility, projection-stale
signaling, reuse of the existing worker, and absence of new persistence,
network, projection, or model authority.
