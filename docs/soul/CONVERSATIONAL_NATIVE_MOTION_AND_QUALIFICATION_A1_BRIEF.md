# Conversational Native Motion and Qualification A1 Brief

Status: Operator-authorized implementation slice

## Purpose

Complete the two active implementation tracks without weakening Visual Studio
authority:

1. let an active reviewed Visual Studio workflow prepare and execute native
   text-to-video generation or a review-led native revision through Chat; and
2. expose one read-only qualification summary over retained motion receipts and
   human reviews so the Operator can compare fidelity evidence with runtime
   cost.

## Conversational native-motion flow

The first slice is deliberately contextual. Chat may start native motion only
from an active creative flow that resolves one exact Visual Studio project and
has either:

- a newly generated still with a recorded `keep` review; or
- an exact existing Visual Studio source, which already resolves only to a
  kept candidate.

The Operator supplies:

- an explicit native-scene request;
- one supported duration: 4, 8, or 12 seconds; and
- a chronological scene direction.

Soul may generate only the optional seed. The proposed duration, direction,
seed, active Core, required Core, runtime profile, frame envelope, estimated
runtime, and external-publication boundary remain visible before execution.
The exact action click authorizes the disclosed Core transition and one bounded
native render.

The resulting WebM returns to Chat as an authenticated video attachment and
remains a Visual Studio motion candidate. Motion review stays authoritative in
Visual Studio for this slice. A recorded `revise` review may then be continued
through Chat by an explicit revision request containing a replacement
direction. The revision preserves the reviewed source candidate, defaults to
its duration unless the Operator explicitly selects another supported
duration, generates a new seed, and requires another exact action click.

## Qualification summary

The qualification summary is a read-only projection of existing Visual Studio
projects, immutable motion receipts, and human motion reviews. It may report:

- generation kind and profile;
- duration and delivered frame rate;
- elapsed render time and runtime-to-output ratio;
- delivery method;
- human disposition, rating, and notes;
- reviewed versus unreviewed counts and supported-duration coverage.

It must not infer aesthetic success, alter a review, generate media, or promote
a profile. The Operator remains the qualification authority.

## Boundaries

- No automatic retry, queue, watcher, scheduler, daemon, unattended
  continuation, upload, or publication.
- No model output authorizes a Core transition or render.
- No motion is silently marked kept, qualified, bound, or production-ready.
- Image-guided motion, motion deletion, motion-to-music binding, and external
  publication retain their existing exact Dashboard gates.
- Skill Studio promotion, Self Augmentation mutation, and Review Center
  authority remain Dashboard-only because their structured evidence and
  destructive or code-changing scope are not appropriate for a generic chat
  mapping.

## Acceptance

- Ordinary discussion does not invoke motion generation.
- Missing duration or direction stops at `awaiting_input`.
- Stale Chat or downstream digests mutate nothing.
- Exact generation and revision reuse `VisualStudioService` preview/execute
  gates and AMD generation lease behavior.
- Chat returns the authenticated WebM and does not claim publication.
- Revisions require a stored `revise` review and preserve immutable lineage.
- Qualification output is deterministic, read-only, and visibly distinguishes
  measured evidence from pending human judgment.
- Existing creative, Core, Visual Studio, and publication regressions pass.
