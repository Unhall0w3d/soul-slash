# Memory Live Qualification A14 Brief

## Status

Human-authorized supervised qualification slice, 2026-08-24.

## Objective

Prove the accepted A10-A13 memory chain against the real local runtime before
any unattended lifecycle worker is introduced. A14 captures one ordinary
Dashboard chat exchange, makes one bounded local GPT-OSS proposal request,
applies deterministic admission, verifies ordinary approved-memory retrieval,
then compensates the qualification transaction and verifies restart-safe audit
and observation evidence.

## Execution and authority

- Execution is explicit, foreground, bounded, and terminal.
- The existing Dev Core coordinator may temporarily place chat on Soul-Lite,
  start GPT-OSS on the AMD lane, perform one request, unload it, and restore the
  prior eligible Core. If Dev Core is selected, its resident runtime is reused.
- GPT-OSS may return proposals only. It receives no lifecycle authority.
- A13 policy exclusively decides admission from verified evidence and fixed
  thresholds.
- A10 transaction compensation appends reversal events; it never rewrites or
  physically deletes observations, proposals, decisions, or canonical history.
- The A14 command may compensate only a rollback reference retained by an A14-
  prefixed qualification decision. It cannot act as a general memory rollback
  surface.
- All public command receipts remain content-free. Owner-private source and
  derived text stays inside the ignored local memory boundary.

## Bounds

- One A11 batch: at most 24 observations, 12 exchanges, and 48 KiB of text.
- One GPT-OSS request with low reasoning, zero temperature, 2,048 output-token
  ceiling, a 16,384-token context ceiling, and a closed JSON schema.
- At most eight proposals; A12 and A13 retain their existing limits.
- No timer, watcher, daemon, scheduled task, retry loop, remote database,
  cloud model, Qdrant, FalkorDB, Redis, external export, or physical deletion.

## Qualification sequence

1. Verify the canonical audit baseline, observation chain, derivation chain,
   and admission chain.
2. Submit one clearly labeled, harmless ordinary fact through actual Dashboard
   Chat and verify the retained A11 exchange.
3. Run one local derivation and inspect its content-free model and packet
   receipt.
4. Run deterministic A13 admission and prove the admitted record is available
   through the ordinary approved-memory retrieval service.
5. Compensate each qualification transaction, prove retrieval abstains, and
   verify the complete audit chain.
6. Restart the Dashboard and repeat integrity/status checks.

## Acceptance

- The real chat route captures exactly one user/assistant pair without changing
  chat success semantics.
- Model settings and schema match this brief, and runtime/Core restoration is
  evidenced.
- Derivation, admission, retrieval, and rollback terminate visibly with
  content-free receipts.
- Failed local synthesis cannot advance the A12 cursor or mutate canonical
  memory.
- Transaction compensation removes the qualification memory from retrieval
  while preserving immutable evidence and audit history.
- Restart does not invalidate audit, observation, derivation, or decision
  chains.
