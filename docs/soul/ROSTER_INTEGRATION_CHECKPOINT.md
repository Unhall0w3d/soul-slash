# Roster, CPU and Creative Studio source checkpoint

This source checkpoint connects the current roster, resident CPU member and
Creative Studio workflows. It is a reviewed source snapshot, not a portable
installer, blanket skill release or claim that every historical repository test
passes. Local deployment evidence, journals, approved memory, enrollment data,
credentials, generated media and machine-recovery records are intentionally
separate and are not distributed with this checkpoint.

The public tree includes a source-only navigation fixture reproduced from three
files already present in its public parent commit. Its provenance identifies that
public parent; the original deployment enrollment/private provenance is excluded.
This public fixture is for reproducible source-navigation checks, not a migration
binding for existing deployment journals. Existing installations must retain their
own enrolled snapshot and exact journal bindings.

## Available paths

- Model-specific roster adapters, bounded runtime ownership, safe switching,
  cancellation/recovery and versioned durable conversation histories.
- A CPU member with scoped approved-memory retrieval, a validated calculator,
  explicit task controls and confirmation-bound deferred GPU work.
- Read-only operational requests, reviewed source navigation and bounded
  reference requests through the existing authenticated conversation gateway.
- Creative brief preview, exact native preparation/generation approval, shared
  compute handoff and protected result delivery for images and music.
- Process-local reuse of complete asset-hash proofs, with file identity checks
  and independent cancellation. Cold or changed assets receive full SHA-256
  verification.
- An operational dashboard for compute availability, system status, workspace,
  vocabulary, creative review and administration; LibreChat is the chat client.

## CPU reference requests

New reference-enabled CPU conversations support `Weather in CITY`,
`Lookup: TOPIC`, `Research: QUESTION`, `Show reference roots`,
`List files source: .`, `Read file source: NAME.rb` and
`Search guides: WORDS`. `guides` is the other fixed file root. These routes
collect bounded reference data without model inference; source content cannot
authorize actions. Research requires an explicitly configured existing provider.
Public instant-answer lookup is a separate, more limited reader.

The roots are the repository's source and guide directories, not a general home
directory browser. Guide content may be locally sensitive and must not be
forwarded to public services or published automatically. Downloads Markdown
requires manual full-file review and manual relocation before agent access.
Paths, aliases, hidden files, secrets, hardlinks and output bounds are checked.
Helpers have owned process groups, deadlines and cancellation cleanup.

Reference presentations are compact and explicitly incomplete when bounded.
Directory presentation shows the first ten inspected entries; guide search shows
at most three of its bounded matches. Full bounded metadata and source digests
stay in the local receipt. These controls do not increase model context: the
currently qualified CPU path retains 4096 context tokens and up to 1024 output
tokens. Start a new conversation when its window is full.

## Validation boundaries

The reference integration's consolidated deterministic checks cover 138 tests /
658 assertions, including inherited CPU/creative behavior, authenticated HTTP,
earlier journal versions, exact history/replay, cancellation, process limits,
file boundaries and a real child-interpreter check. The invocation catalog has
20 checks. Browser acceptance additionally exercised sequential compact file and
guide requests, quarantine messaging, public lookup, current weather and exact
replay. A missing research provider remains a blocked configuration, not a pass.

The local activation retained prior journals rather than rebinding them. Older
reference variants remain loadable because their original source and replies are
frozen. The latest variant changes only new conversation bindings. The bounded
helper launch includes the current Ruby interpreter's directory so the existing
native weather runner works without a system Ruby installation or a global PATH
change.

Independent human approval remains necessary for memory changes, destructive
actions, private-data transfer, network/power changes and artifact promotion or
publication. Administrative conversation routes, broader contexts, member-to-member
review, production video workflows and voice qualification remain separate work.
