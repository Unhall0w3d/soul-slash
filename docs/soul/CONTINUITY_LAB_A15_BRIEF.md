# Continuity A15: foreground usability and conversation pilot

## Authorization, question and fixed scope

The owner authorized the foreground usability trial and assessment, adding that
it should include generic conversation, not just tasks. This brief records that
scope. Use the existing isolated lab; no ordinary Soul memory or dashboard
activation, services, model switching, network/power changes or Git promotion.
Primary owns live work, source/effect verification and final assessment.

Question: can the frozen A13 practical profile handle ordinary requests, changed
decisions and casual conversation when exact tools and note operations are not
prescribed? A14 is a historical directed-task reference, not a matched control.
There is no causal comparison or population reliability estimate in this pilot.

Three independent fresh-store batches, four events each, run sequentially:

1. `planning`: fictional projector recommendation, changed choice/quantity,
   later recall of that decision, and a delivery detail never supplied.
2. `holdout`: a no-tool uppercase request, garden-supply calculation, changed
   quantities and later recall. Freeze before planning results; do not tune it.
3. `conversation`: a casual greeting after a walk, natural follow-up, change of
   beverage, and later callback to beverage and reason for the walk. These are
   fictional test utterances, not user facts for ordinary memory ingestion.

Each batch: at most 24 generations and 1800 seconds with 20-second cleanup
reserve; six calls/event, existing 60/420/430-second HTTP/event/worker limits.
Model/build/template, PID identity, sampler, grammar, guide, actual token packing
and 3072-input-token profile remain frozen against A13. No automatic repeats,
prompt changes after observing results, or adaptive hints within this pilot.
Failures are results to assess, not prompts to optimize until all are green.
Stop an affected batch on ambiguous intent/infrastructure failure; no replay.

New worker/broker per event. No previous conversation automatically supplied;
existing lexical history/notes/corpus retrieval is available. This measures the
current retrieval-dependent lab, not normal recent-history chat UX, a restarted
model server or a power-loss experiment. Search requires nonempty lexical terms
and there is no listing tool. These interface limits must inform interpretation.
No note creation, content, IDs or timing is mandated. A decision not to write a
note is not failure. Observe unnecessary notes and later use without conflating
notes with verified knowledge or interpreting compliance as spontaneous learning.

## Acceptance and measurement, declared before inference

Retain exact requests, corpus, criteria, code/config hashes, outputs, tool traces,
durable notes, tokenizer/timing receipts and fresh-worker/idle read-back.
References and expected facts stay outside model requests. Corpus search/read
routes and meaningful alternative phrasing are allowed; no exact action order
or verbatim final answer is required except the explicit uppercase request.

Mechanical screening checks terminal replies, expected fact tokens or declared
uncertainty patterns, required retrieved support, clean initial contexts, replay
of actual tool effects and exact resulting notes. Validate each recorded tool
result against existing deterministic Actions/Retrieval and before-state; do not
accept fabricated evidence or a plausible answer without required sources.
Prior-note support must actually come from a note existing before the event.
Callbacks require completed earlier user exchanges (not necessarily correct
earlier answers); a missing exchange is skipped, not silently reconstructed.

Machine screening is necessary, not final semantic judgment. Primary reviews
all replies/traces for correctness, negation/contradiction, relevance, unsupported
claims, conversational naturalness, appropriate follow-up and operator repair
burden against the fixed cases. No model judge grants safety/promotion authority.
The first three conversation turns are semantic-review cases, not factual-pass
claims from nonempty text. Report mechanical screening and primary assessment
separately. Any false-positive/negative in screening is reported, not silently
rescored by changing the criterion after seeing output.

Report first-attempt per-case outcomes, completed/failed/interrupted/skipped
categories, calls, elapsed time and available token/timing data, optional-note
choices and retrieval sources. No repeat-based reliability claim; unknown usage
is unknown. Final human acceptance remains the owner's, not the evaluator's.

`verify-continuity-lab-usability-a15.rb`, this brief/review and canonical links.
Reuse the A14 bounded runner pattern without modifying historical harnesses or
the frozen runtime. A narrow verifier must cover synthetic positive/negative

checks. Use actual isolated synthetic workers before live testing. Reuse passing
runtime regressions whose frozen code is unchanged; run syntax and docs checks.
Preserve dirty work and historical evidence; verify hashes and stores at closeout.
